What changed

In the 1.4.9 source, Relic.CUPID_BOW specifies a 65-tick cooldown (3.25 seconds at normal tick rate). RelicItem.releaseUsing fires the arrow and starts that cooldown. RelicItem.properties assigns the same vanilla Rare tier to the bow as to the other relics.

On feature/sakura-renewal the Cupid Bow specifies zero cooldown. A successful release starts no item cooldown, so the player can begin the next draw immediately. Each shot still requires a draw strength of at least 0.15 and uses one durability in Survival. The 14 attack damage, 1.4 attack speed and 1,024 maximum durability remain. Rippleglass Bow keeps its own cooldown. The attack speed attribute is a melee statistic.

The Cupid Bow has vanilla Epic rarity and a gold display name. If Apotheosis supplies its rarity data component, the bow requests apotheosis:mythic. Mythic is the highest default tier found in the pack's Apotheosis 8.9.0 jar. Apotheosis's ItemStackMixin applies the native Mythic color to the item name. In the supplied Apotheosis defaults both that name and the native beam are orange (#ED7014). The standalone name is gold (#FFAA00), and the additional gold particles still surround a dropped bow in both cases. A separate gold particle effect circles the dropped bow, including in installations without Apotheosis. Existing bows that inherited their item defaults also inherit the new presentation. A saved stack with its own explicit rarity component keeps that override. This presentation does not grant extra affixes, damage, or a lower drop chance. Other client or server packs can customize the native beam, rarity label, and color. Actual rendering of the complete pack's beam has not been confirmed.

The supplied source tree includes the Gradle wrapper and project configuration. Runtime libraries normally resolve through Gradle. The repository handoff can be reviewed independently of the author's CurseForge test profile.

Signature artwork
The author supplied the approved bow picture and specified soft pastel pink for the heart gem. tools/generate_cupid_bow.py draws the four 64 by 64 sprites and the in-flight Cupid arrow atlas. The rest, early, half and full-draw sprites share their ribbon loops, gold-rimmed pink heart gems, ivory wing tips and lace detailing. Only the string, limb flex, and the nocked arrow move. ArsenalClient selects the Cupid-specific arrow texture while Rippleglass uses the existing arrow texture.

Bow depth and the string
The four original 64 × 64 color sprites reproduce the approved front artwork. Every pose has a second pair of masked textures for its decorated body and its string. Combining the two visible masks recreates the original pixels, including the lace, gems and feathers. The four explicit item models give both parts a front, a back and colored side faces following each opaque edge. Both lie on the same center plane.

On Minecraft's 16-unit model grid, the previous generated item ran from Z 7.5 to 8.5 for body and string. The decorated body now runs from 7.75 to 8.25 (0.50 units). The laced string runs from 7.9375 to 8.0625 (0.125 units). This halves the body depth and takes seven eighths off the string depth at rest and at each draw stage. The shared cupid_bow_handheld.json defines the shared hand, ground, frame and inventory positioning. With the first-person Z scale of 0.28, the two corresponding local depths are 0.14 and 0.035 units. The third-person scale is 0.9, giving 0.45 and 0.1125 units. Camera perspective changes their screen widths.

To regenerate the editable meshes, run python tools/generate_cupid_bow.py with Pillow. ci/renewal-assets.py checks the packaged artwork and both layers' geometry. The field visit under ci/probe uses the actual Minecraft item renderer.

Beta.2 aiming and visibility
The first-person yaw is mirrored at 46 degrees. The third-person hand models have an eight-degree adjustment. Normal left-click still directs the archer's charmed allies to the target in sight. Every nearby Cupid cue requests Minecraft's particle-limiter override, including the full-draw cue, trail and impact. Personal Sakura range and effects density still apply. NetworkCupid.java and NetworkCupidServer.java exercise two shots through a dedicated server connection. CupidQuadWitnessMixin observes actual rendered heart quads so the test can compare them with pink pixels in the captured frame.

Optional two-target Cupid wish
Hold the bow and crouch-left-click an adult you charmed, then a second nearby charmed target. Click empty air or select the first target again to clear the wish. The first selection lasts ten seconds. When the second is accepted, love hearts appear for one second. If both remain eligible, one baby appears from a participating creature's own offspring factory. Different species are allowed. A player can opt in with /sakura cupid witness on and revoke it with /sakura cupid witness off. Only a creature supplies the baby. The wish itself gives the player no new movement instructions. After success the creatures rest for five minutes and the archer can start another wish after three seconds. This timing belongs to the wish. The archer can start drawing the next arrow immediately after a shot.

CupidWishes.java controls selection, expiry, server validation, visibility of eligible targets to the archer, and offspring creation. AcquisitionPolicy.java defines the server settings for permissions, player witnesses and pair radius (eight blocks by default). CupidPairEvent.java exposes protection vetoes during selection and at completion. Open Parties and Claims supplies an additional ownership check when installed. The data tag uwudimension:wish_excluded can exclude creature types. CupidWishProof.java covers the two orders of a player witness, same-species and mixed pairs, failed or vetoed factories, expired selection and duplicate prevention.
