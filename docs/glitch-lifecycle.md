# Glitch form lifecycle and compatibility

The saved `uwu_form` index continues to address the original 148-entry list. A stack with no form displays and initializes index zero (Cupid Bow). Base damage and speed are calculated from the active form through the NeoForge item-attribute event; existing item component patches are not rewritten. Form-specific use, draw animation, existing melee hooks, and tool actions dispatch against the current form. The original owned Glitch stack is reserved during a physical throw and returned by `RelicReturns`.

After a successful ability, the stack remains pending until its applicable cooldown and ability complete. Counter forms also remain pending for the full 160-tick matching ward, which is longer than their item cooldown. Thrown stacks cannot advance while held in return custody. Bow arrows and scythe waves carry unique action tokens; their actual destruction writes a durable completion receipt to overworld saved data. Unloaded projectiles do not count as completed. Fishing forms track the original hook owner and hook UUID, wait for that hook to finish even if the stack is transferred, and allow its owner to reel while pending. If the original owner is offline while somebody else holds the stack, the form conservatively remains pending until that owner reconnects. The pending state follows the stack when moved or saved. Missing receipts do not guess completion or change the form.

Each used stack gets a random persistent identity. Up to 64 distinct action UUID receipts are retained per identity. This bounds normal per-shot history, but a capped record remains in world data for each distinct used stack, even after the item is destroyed. Deleting a receipt merely because the current inventory has advanced is not proven crash-safe: player, chest, entity and world-data saves are independent. A copied/restored pending stack whose shared identity has accumulated more than 64 later completed actions on other copies may remain pending because its receipt was evicted; distinct action UUIDs ensure it cannot be falsely completed by another action. There is no automatic recovery for this rare stale-copy case.

An optional `@Pseudo` mixin asks Better Combat for the selected form's attributes using a temporary form stack, then uses a shape fallback if the form has no Better Combat registration. It never writes a Better Combat preset into the real stack; an explicitly supplied preset retains precedence. Better Combat is optional. This describes intended compatibility, and actual behavior must be judged against hosted integration tests.
